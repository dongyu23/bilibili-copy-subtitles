# Bilibili / YouTube / 视频号 / 通义听悟 一键复制全部字幕

[![Tampermonkey](https://img.shields.io/badge/Tampermonkey-用户脚本-00485b?logo=tampermonkey)](https://www.tampermonkey.net/)
[![Version](https://img.shields.io/badge/version-2.7.4-00aeec)](./bilibili-copy-subtitles.user.js)
[![License](https://img.shields.io/badge/license-MIT-green)](./LICENSE)

一个轻量的油猴脚本，同时支持 **Bilibili**、**YouTube**、**微信视频号** 和 **通义听悟**。打开有字幕的视频，点击页面左下角的 **复制全部字幕**，即可把整理后的纯文字字幕复制到剪贴板；视频号则通过分享链接把视频语音转成文字；通义听悟则在转写详情页一键复制整篇转写稿。

复制结果保留正文标点，不包含时间戳、字幕序号、JSON 字段或其他字幕文件边界符号，适合整理笔记、检索内容和制作摘要。脚本会按当前视频和分 P 缓存字幕列表及正文，重复读取时不会重新随机匹配其他视频的字幕。对于没有字幕的视频，可以在设置 StepFun API Key 后回退到语音识别，自动生成可复制的纯文字内容。

## v2.0.0 新特性

- **章节选择**：从播放器接口读取视频章节，识别前可选全篇或自由勾选任意章节组合；没有章节的视频不弹面板，行为与之前完全一致。章节模式下输出带 `【章节名】` 分隔。
- **流式分段识别**：HTTP Range 滑动窗口边下边切，按 moof 边界分片，稳态内存与视频长度无关（7 小时视频从 600MB+ 降到约 50–80MB）。
- **断点续传**：分片级 checkpoint 写入扩展存储，中断后重跑自动跳过已完成分片；油猴菜单可一键清除断点。
- **本页执行 + 内存护栏**：流式分段把内存压到与视频长度无关的低位；另有堆内存看门狗（占用超 60% 暂停等待回收、超 80% 主动中止保护页面），分片间主动让出主线程，识别期间页面保持响应。
- **有界并发**：在途分片总字节设上限，大片自动降并发。

## 安装

安装前需要浏览器扩展 [Tampermonkey](https://www.tampermonkey.net/) 或其他兼容 UserScript 的脚本管理器。

### 一键安装

[点击安装脚本](https://raw.githubusercontent.com/dongyu23/bilibili-copy-subtitles/main/bilibili-copy-subtitles.user.js)

Tampermonkey 打开安装确认页后，点击“安装”即可。脚本后续可以通过脚本管理器自动检查更新。

### 手动安装

1. 打开 Tampermonkey 管理面板。
2. 新建脚本并删除编辑器中的默认内容。
3. 将 [`bilibili-copy-subtitles.user.js`](./bilibili-copy-subtitles.user.js) 的全部内容粘贴进去。
4. 保存脚本并刷新视频页面。

## 使用

1. 打开一个带有字幕的视频（Bilibili 视频/番剧播放页，或 YouTube 视频页）。
2. 在页面左下角的语言下拉框中选择字幕语言，默认是 **中文（默认）**，也可以选择英文、日文等其他语言。
3. 点击 **复制全部字幕**。
4. 页面显示复制成功及字符数量后，字幕正文已经进入剪贴板。

视频带有章节信息时（B 站进度条上可见的分段），点击复制后会先弹出章节面板：默认「整篇（不分章）」，直接点开始复制即与之前完全一致；取消整篇并勾选任意章节，则仅复制所选章节的文字，每章以 `【章节名】` 开头。没有章节的视频不弹面板，详见下文「按章节复制」。

多分P（按选集分段）的视频，右侧“视频选集”面板标题栏有「跨集复制」按钮，可勾选任意集数一次性复制多集字幕，详见下文「跨集复制（按选集）」。

也可以从 Tampermonkey 菜单执行“复制当前视频全部字幕”。如果不想显示页面按钮，可以通过菜单中的“显示/隐藏页面按钮”关闭它。

YouTube 链路通过 YouTube 官方的 InnerTube 播放器接口读取字幕轨与音频直链，无需登录；个别视频可能受所在网络环境能否访问 YouTube 影响。B 站链路不变，部分视频只有登录后才能读取字幕列表。

视频号链路见下文「视频号转文字」：点左下角的 **视频号转文字** 按钮，粘贴分享链接即可。想转写本地文件（比如用其它工具下载的视频、录音），点 **上传转文字** 选择文件即可，走同一套识别链路。页面左下角还有一个不显眼的齿轮按钮（⚙，鼠标悬停才清晰），点击或从 Tampermonkey 菜单「设置」进入集中设置面板，管理 API Key、识别端点与语言、调试开关、元宝 Cookie 和缓存留存时间。

- 一键复制当前视频或当前分P的完整字幕（B站 / YouTube / 视频号 / 通义听悟）
- 字幕直链过期（CDN 返回 403）时自动换取新直链重试，失败给出可操作提示
- 自动去除时间戳、序号和字幕格式边界
- 保留字幕正文原有标点
- 中英文相邻字幕行自动补充必要空格
- 支持普通视频、分P、合集、播放列表和番剧播放页
- YouTube 字幕轨自动列出全部语言，默认优先中文
- 有字幕且带章节的 B 站视频支持按章节复制：整篇或自由勾选章节组合，章节输出带 `【章节名】` 分隔
- 多分P（按选集分段）视频支持跨集复制：右侧“视频选集”旁的「跨集复制」按钮可勾选任意集数，逐集获取字幕后按 `【Pn】【标题】` 分段拼接，详见下文「跨集复制（按选集）」
- 跨集复制中无字幕的集自动回退 StepFun 语音识别：与单视频链路共用缓存键，识别结果按集留存，重复复制或换用主按钮都不再重复识别计费；平台有字幕的集一律原样使用平台数据，不做重新识别
- 无字幕视频可回退到 StepFun 语音识别，生成纯文字内容（B站 / YouTube 均支持）
- 视频号转文字：粘贴分享链接即自动完成「解析 → 下载 → 语音识别 → 剪贴板」
- 上传转文字：选择本地视频/音频文件，经同一套 StepFun 语音识别转成文字
- 通义听悟转写：在转写详情页一键复制整篇转写稿，详见下文「通义听悟转文字」
- 字幕检索：B 站视频页按 Ctrl/Cmd+F 检索当前分P的字幕，命中项带时间点、可上下切换并跳转播放进度；「全部字幕」模式可不输入关键字直接逐条点击跳转，详见下文「字幕检索（Ctrl+F）」
- 语音识别 Key 图形化配置面板，支持一键测试连接
- 元宝 Cookie 支持一键读取与登录态测试，解析/取直链失败时给出可操作的错误原因
- 设置面板集中管理：Key、识别端点、识别语言、调试开关、元宝 Cookie、缓存留存时间
- 识别过程可视化：阶段、进度条、实时耗时
- 识别耗时统计：开始前预估、完成后展示实际用时
- 音频下载失败自动换取新的播放数据地址重试，并依次尝试备用 CDN 地址
- 字幕/识别结果缓存留存时间可配置（会话 / 1 小时 / 24 小时 / 7 天 / 30 天 / 永久）
- 页面按钮支持显示或隐藏
- 原生请求失败时自动尝试油猴跨域请求；全部请求点均有兜底，底层网络错误分类为可操作的中文提示（区分代理/扩展/@connect/超时，服务端错误不会被误报成连接问题）
- 支持 Tampermonkey 自动更新

## 字幕选择规则

脚本默认优先复制中文字幕；每个视频第一次读取时会加载该视频实际提供的字幕语言列表：

1. 语言代码为中文或 AI 中文的字幕
2. 名称包含“中文”“汉语”“简体”或“繁体”的字幕
3. 非 AI 字幕
4. 如果以上条件均不满足，使用视频提供的第一条字幕

选择过具体语言后，在同一视频分 P 内再次读取会沿用该选择；切换到其他视频或分 P 时会恢复为中文默认选项。

B 站会复用播放器当前页面已经发出的带签名字幕请求，避免旧接口返回其他视频字幕。YouTube 则按视频 ID 直接请求官方播放器接口，字幕列表与语言名称以接口返回为准。

## 按章节复制

B 站视频带有章节信息（进度条上可见的分段，且不少于 2 个）时，点击 **复制全部字幕** 后会先弹出章节面板：

- **整篇（不分章）**：与之前行为完全一致，复制整段字幕文字；
- **勾选任意章节组合**：仅复制所选章节的字幕，每章以 `【章节名】` 单独成行开头，章节之间空行分隔，格式与无字幕视频语音识别的章节模式一致。

面板提供「全选/清空」快捷切换，方便一键复制“带章节标题的完整文稿”；也可以只勾选其中几章，复制局部内容。章节按字幕条的起始时间归属：章节起点之前的内容并入第一章，最后一章之后的内容并入末章，因此全选时不会丢文字；没有字幕对应的章节不会产生空标题。

没有章节的视频（以及 YouTube、视频号链路）不弹面板，行为与之前完全一致。章节列表按 `视频:分P` 缓存，重复点击不会重复请求播放器接口；所选章节的复制结果按 `视频:分P:语言:章节组合` 隔离缓存，整篇与各章节组合互不影响，重复点击同一组合不重复下载字幕。

## 跨集复制（按选集）

按选集（多分P）分段而非按章节分段的视频（课程、合集类最常见），右侧“视频选集”面板标题栏会出现「跨集复制」按钮（单分P视频不显示）。点击后弹出选集面板：

- **全部选集**：默认勾选，直接复制全部分P的字幕；取消后可自由勾选任意集数组合；
- **字幕语言**：面板内可选语言（选项来自首个分P实际提供的字幕轨），默认“自动（中文优先）”；所选语言在某集缺失时该集自动回退为中文优先；
- **输出格式**：每集以 `【Pn】【标题】` 单独成行开头，集与集之间空行分隔，集内文字与单视频复制一致；
- **进度与取消**：复制过程中面板底部显示“正在获取（已完成/总数）”，可随时取消，取消后不写剪贴板；
- **无字幕集回退语音识别**：某集没有字幕时自动回退 StepFun 语音识别（与单视频无字幕兜底同一条链路，含进度面板、耗时统计与历史记录），识别结果按集写入缓存，之后再次跨集复制或在该集上使用「复制全部字幕」都直接命中缓存，不会重复识别计费；批量场景的确认只在本次运行首次遇到无字幕集时询问一次，选择取消则本次运行跳过其余无字幕集的识别；未配置 StepFun Key 时跳过识别并在提示中说明；识别结果缓存命中时不需要再次确认。平台有字幕的集一律原样使用平台数据，不做任何重新识别；
- **结果提示**：完成后提示复制集数与字符数；某集无字幕或获取失败时跳过并在提示中列出（形如 `未获取到：P1、P7`）。

跨集字幕列表走 WBI 签名的 `/x/player/wbi/v2` 接口（与播放器自身请求同源，避免未签名旧接口返回错乱数据），单集缺失语言时按与单视频一致的规则回退。字幕列表与正文按 `视频:分P:语言` 隔离缓存，与「复制全部字幕」互通，重复点击不重复下载。AI 字幕需要登录 B 站账号后才可见。

字幕相关缓存分三类，都以 `视频:分P:语言` 隔离：

| 前缀 | 内容 | 说明 |
| --- | --- | --- |
| `video-subtitles-meta-v6:` | 字幕列表（含直链） | 直链带 `auth_key`、有效期短 |
| `video-subtitle-lines-v1:` | 原始字幕行（紧凑文本，`from\tto\tcontent` 每行一条） | **整篇、章节、检索、跨集四条链路共用这一份**；最多保留 8 条，超额按写入顺序淘汰；**仅会话级，不写 GM 持久层** |
| `video-subtitles-body-v6:` | 语音识别结果、视频号转写 | 这些没有时间戳，无法从字幕行派生 |

整篇复制、按章节复制、Ctrl+F 检索、跨集复制都从同一份字幕行各自派生文本，不再为每个章节组合各存一份拼接字符串——既避免重复占用，也让「整篇取过一次」之后章节直接可用，无需再拉一次。

字幕行用制表符分隔的紧凑文本存储，不用 JSON 数组——后者要为每条重复一遍 `{"from":…,"to":…,"content":…}` 键名，2356 条就要多出几十 KB 纯键名。实测落盘体积约为 JSON 的 **0.57**（296 条字幕 15KB → 9KB）。

同时字幕行缓存**最多保留 8 条**，超额按写入顺序淘汰最早的。长视频一集就上百 KB，看过的视频一多会把 `sessionStorage`（浏览器配额约 5MB）和 GM 存储撑爆——超额后每次 `setItem` 都会抛 `QuotaExceededError`，缓存会静默失效。

## 缓存与留存时间

字幕列表、字幕正文和语音识别结果都按 `视频:分P:语言` 隔离缓存，重复点击不会重复下载或重复计费。缓存的留存时间可以在 Key 配置面板中调整：

| 选项 | 行为 |
| --- | --- |
| 仅本次会话（默认） | 刷新页面保留，关闭标签页后清除 |
| 1 小时 / 24 小时 / 7 天 / 30 天 | 写入浏览器本地存储，超过对应时间后自动失效 |
| 永久 | 一直保留，直到手动清除 |

打开 Tampermonkey 菜单的「设置 StepFun API Key 与缓存」即可修改留存时间、查看已缓存条目数，也可以一键清除全部字幕缓存。缓存只保存在浏览器本地，不会上传到服务器。

## 无字幕视频的语音识别兜底

当视频没有任何字幕时，脚本可以下载该视频的音频轨道，通过 StepFun 语音识别接口（`stepaudio-2.5-asr`）生成纯文字内容。兜底与字幕链路完全独立，不影响原有行为。

### 开启方式

1. 从 Tampermonkey 菜单执行「设置 StepFun API Key（无字幕视频语音识别）」，在弹出的面板中粘贴 [StepFun 开放平台](https://platform.stepfun.com/interface-key) 的 API Key（需订阅 Step Plan），点击「测试连接」确认可用后「保存」。也可以直接点击无字幕视频的「复制全部字幕」，脚本会自动弹出该面板。
2. 打开无字幕视频，点击 **复制全部字幕**。
3. 首次使用会弹窗确认：将下载音频并上传到 StepFun 识别（会产生费用），确认后开始识别。
4. 识别完成后文字直接进入剪贴板，提示样式与字幕复制一致。

### 进度与耗时

识别过程中页面左下角会显示实时进度面板，包含三个阶段：

- **正在下载音频**：显示已下载/总大小与百分比（通过油猴请求获取真实进度）；
- **正在识别**：多分片时显示并行状态（如 `并行 3 段 · 已完成 1/4 段`），进度按音频时间轴推进（识别接口的增量结果带时间戳）；
- 面板右下角实时显示已用时间，全部阶段统一计时。

确认对话框会根据历史记录给出预估用时；完成后提示中会展示实际用时，例如「已通过语音识别复制，共 3971 个字符 · 用时 13.9 秒」。脚本在本地保留最近 20 次识别的音频时长与耗时，预估随使用越来越准。短于 12 MB 的音频一次请求完成，超过则自动分片、最多 3 片并行识别（并发数见源码 `ASR_CONCURRENCY`）。

不配置 Key 时，无字幕视频仍保持原来的「当前视频没有可用字幕」提示，不会产生任何请求。

### 工作方式

- **B 站**：通过播放接口（`/x/player/playurl`，番剧为 `/pgc/player/web/playurl`）获取当前分 P 的 DASH 音频流，选择码率最高的普通 AAC 音轨；无签名直连被风控时，自动复用播放器自己发出的带签名请求。
- **YouTube**：通过 InnerTube 播放器接口（Android 客户端上下文）获取音频直链，选择体积最小的 m4a 音轨以控制请求体大小，同一响应中的其他 m4a 地址作为备用 CDN。
- 下载完整音频后按 MP4 片段（`moof` 边界）分片，每片重新拼上头信息后独立送识别，多片同时上传、结果按原顺序拼接，长视频也不会超限；结果按缓存策略保留，重复点击不会重复计费。
- 音频地址全部下载失败时（直链过期、CDN 节点拒绝等），脚本会自动重新拉取播放数据换取新地址再试，仍失败才提示错误。
- 语音识别默认使用 `zh`，可在脚本源码顶部修改 `ASR_LANGUAGE`。实际接口对中英文音频均可转写。
- 计费按音频时长计算（`stepaudio-2.5-asr` 约 0.15 元/小时），具体以 [定价页](https://platform.stepfun.com/docs/zh/guides/pricing/details) 为准。

### 注意事项

- 脚本默认不内置 Key，首次在无字幕视频上点击复制时会自动弹出配置面板；Key 只保存在浏览器本地，不会上传到其他服务器。
- 语音识别会把音频上传到 StepFun，请仅用于有权转写的内容。
- 部分视频（如会员专属音轨）可能拿不到音频流，脚本会提示重新播放后重试。

## 视频号转文字

微信视频号没有可复制的字幕接口，脚本通过「元宝解析分享链接 → 获取视频直链 → 语音识别」把视频语音转成文字，全程无需安装其他软件、不修改系统代理。

### 使用方式

1. 点页面左下角的 **视频号转文字** 按钮（B 站 / YouTube / 视频号页面都能看到；在视频号页面会自动带入当前视频的短链）。
2. 粘贴视频号分享链接（在微信里点视频右上角 `・・・` → 复制链接，形如 `https://weixin.qq.com/sph/xxxx`），点 **开始转文字**。
3. 首次使用会弹窗确认（音频会上传至 StepFun，按时长计费）。
4. 进度面板依次显示「解析分享链接 → 获取视频信息 → 下载视频 → 识别」，完成后文字自动进入剪贴板，并显示在面板文本框中可再次复制。

### 前置配置（一次性）

- **StepFun API Key**：与另外两个站点共用，在设置面板填写。
- **元宝 Cookie**：点设置面板里的 **打开元宝** 按钮并扫码登录，然后点 **一键读取 Cookie** 即可自动读取全部字段（含 HttpOnly，已自动过滤统计类参数）并保存。若自动读取不可用（非 Tampermonkey 管理器），再按 `F12` → `Application/应用` → `Cookies` → `yuanbao.tencent.com` 全选复制，粘贴到设置面板的「元宝 Cookie」输入框。Cookie 过期后按同样方式更新即可。
- 两个接口都要求在浏览器环境内调用（服务端有 TLS 指纹校验），因此必须通过油猴脚本发起，不能用命令行工具替代。

### 工作方式与限制

- 小于 20MB 的视频整包送给 StepFun（接口原生支持 MP4 容器，由服务端提取音频，无需本地 ffmpeg）；超过则用浏览器内置解码器提取 16kHz 单声道音频后分片送识别。
- 已加密的视频号视频暂不支持（脚本会明确提示），未加密的常规视频可直接转换。
- 仅允许在微信 App 内观看的内容（直播/回放、部分受限内容）取不到视频流，脚本会在开始识别前明确提示，无法转写。
- 图集/图文作品没有音轨，无法转写。
- StepFun 单次请求上限约 30 分钟音频；更长的视频需要分段处理。
- 转写结果按视频缓存，重复点击同一链接不会重复计费。

### 视频号转文字排障

转写失败时，面板状态行和提示 toast 会给出具体原因，按提示对应处理即可：

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| 该内容仅支持在微信 App 内观看 | 链接指向直播/回放或受限内容，微信只允许在 App 内播放，网页与元宝都取不到视频流 | 换一个普通视频的分享链接 |
| 该内容暂时无法播放 | 内容已删除、下架或受限 | 换一个公开视频 |
| 元宝未从该链接解析出可播放的视频 | 元宝认得链接但给不出视频地址（多为上述 App 限内容，或图集/图文作品） | 同上；图集/图文没有音轨，本就无法转写 |
| 元宝 Cookie 已失效或未登录 | 元宝登录态过期（Cookie 有有效期，通常数天） | 设置面板点「打开元宝」重新扫码登录，再点「一键读取 Cookie」，可用「测试 Cookie」验证 |
| 元宝解析失败（附接口原文） | 链接不被元宝支持（如非视频链接） | 确认粘贴的是单个视频的分享链接（`weixin.qq.com/sph/…`） |
| 获取视频信息失败：permission verification failed | 解析出的 token/eid 已过期 | 重新复制分享链接再转一次 |
| 未获取到视频地址 | 视频已删除或仅作者可见 | 换一个公开视频 |
| 该视频已加密 | 视频号对该视频做了加密 | 暂不支持，换普通视频 |
| 语音识别接口返回 HTTP 401/403 | StepFun Key 无效或欠费 | 设置面板重新填写 Key，点「测试连接」验证 |
| 下载视频时 HTTP 403 | 网络代理干扰了 finder CDN | 检查代理规则，确认 `channels.weixin.qq.com`、`finder.video.qq.com` 直连或稳定节点 |

排查任一环节前，建议先在设置面板打开「调试」开关，控制台会输出解析、直链下载、识别各阶段的详细日志。

## 上传转文字

除了页面里的视频，也可以直接转写本地文件：点左下角的 **上传转文字** 按钮，选择视频或音频文件即可，适合转写用其他工具下载的视频、录音、播客等。

长视频可能有上千条，列表按 400 条一批滚动续载，不会一次性建满 DOM。

### 长视频下的性能

字幕检索的两处成本都做了窗口化处理，首屏开销与字幕总量脱钩：

- **命中列表按批渲染**：一个高频词在长视频里可能命中上千条（实测「的」919 条），一次性建满 DOM 会触发大面积布局重绘，在 B 站这种重页面上就是肉眼可见的卡顿。现在命中列表与「全部字幕」共用同一套窗口化渲染——先渲染 200 条，滚动到接近底部再续批，当前项恒在首批内。
- **持久层写入延后**：长视频字幕行可达数百 KB，`GM_setValue` 是同步的扩展存储调用。现在内存与 `sessionStorage` 立即写入（本次使用立即可用），持久层写入延后到空闲帧执行，不再占点击/按键的关键路径。

实测（2356 条字幕 / 203KB）：写 `sessionStorage` 1.9ms、读 0.7ms、检索 0.5ms、渲染 200 行 1.3ms——缓存本身的 JS 开销很小，卡顿主要来自渲染规模，这也是上面两项针对的点。

## 常见问题

### 提示“当前视频没有可用字幕”

该视频可能没有 UP 主字幕或 Bilibili AI 字幕（YouTube 则可能没有字幕轨）。也可能是账号未登录，登录后刷新页面再试。如需在无字幕时自动生成文字，请参考上文「无字幕视频的语音识别兜底」配置 StepFun API Key。

### YouTube 页面没有反应

确认当前网络可以访问 YouTube。脚本只读取公开的播放器接口，不需要登录；如果网络本身无法连接 YouTube，脚本会提示读取失败。

### 安装新版后行为没有变化

在 Tampermonkey 编辑器中确认脚本顶部的 `@version`。如果仍是旧版本，请删除旧内容后重新点击一键安装链接，并刷新视频页面。

### 点击后显示网络请求失败

确认脚本管理器已经授予对应站点的跨域访问权限（B 站为 `api.bilibili.com` 和 `aisubtitle.hdslb.com`）。升级或重新安装脚本时，Tampermonkey 可能会再次显示权限确认页面。

### 提示“无法连接 xxx”

从 v2.6.1 起，底层网络错误会带上域名和性质，不再是一句没有信息量的 `Failed to fetch`。提示里已列出最可能的三种成因，按顺序排查即可：

1. **代理/VPN**：把该域名路由到了失效节点。关闭代理，或把提示里的域名设为直连。
2. **浏览器扩展**：广告拦截/隐私类扩展阻止了请求。用无痕窗口（禁用扩展）试一次即可区分。
3. **`@connect` 未授权**：Tampermonkey → 管理面板 → 该脚本，确认提示里的域名在允许列表内。

若提示写的是「浏览器与油猴两条请求通道都失败了」，说明两条独立通道都不通，基本可以确定是网络层或权限问题，与 Key 无关。

反之，如果提示是「xxx 请求失败：<服务端原文>」，说明链路是通的、服务端返回了错误（例如 StepFun 的 `audio.data or audio.url is required`、配额不足等），按服务端原文处理即可——这类错误不会被误报成连接问题。

### 复制字幕时提示“字幕下载被拒绝”

字幕直链带有效期，页面开太久或切过 P 之后直链会过期，CDN 返回 403。脚本会自动重新拉取字幕列表换取新直链重试，多数情况点击一次即可成功，无需手动刷新。如果仍提示被拒绝，按提示操作：刷新视频页面后重试；使用代理时确认 `*.hdslb.com` 等字幕 CDN 域名走直连而非海外节点（海外/机房节点常被 CDN 拒绝）。

### 语音识别提示“音频下载失败”

音频直链可能已过期或被 CDN 节点拒绝，脚本会自动换取新地址重试；多次重试仍失败时，请稍后重试或更换视频。个别网络环境（代理、公司网络）可能拦截视频 CDN，需要切换网络后重试。

### 视频号提示“元宝解析失败”

元宝 Cookie 已过期或复制不完整（需包含 HttpOnly 项）。按「视频号转文字 → 前置配置」的步骤重新获取并粘贴到设置面板。

### 视频号提示“该视频已加密”

该视频号内容启用了加密，暂不支持自动转写，换用未加密的常规视频即可。

### 为什么复制结果没有换行

字幕通常按短句切分。脚本会移除这些显示层面的分段并拼接为连续正文，同时保留字幕内容中真正存在的换行。

### 为什么 AI 字幕复制出来没有标点

脚本不会增删任何标点符号——复制文本的标点与数据源完全一致。B 站 AI 字幕（`ai-*` 轨道）的源数据本身就不含标点，播放器里显示的同样没有，这是 B 站 AI 字幕生成管线的现状，不是复制过程丢失。实测依据：对多分P视频 `BV1ADpxz9E9V` 逐条检查 182 条 AI 字幕 content 字段为 0 标点，开启播放器 CC 后读取渲染字幕与 JSON 逐字一致；up 主上传的 CC 字幕、StepFun 语音识别结果、YouTube 字幕中真实存在的标点都会被完整保留。平台有字幕时脚本一律原样使用平台数据，不做重新识别。

### 行拼接的空格规则

字幕逐条轮番出现，两条字幕之间就是自然断句点。拼接成连续正文时：每两条之间保留一个基础空格；若边界处已有标点（上一行以标点结尾，或下一行以标点开头），标点本身就是边界，不再重复加空格。这样带标点的字幕输出与标点排版一致；B 站 AI 字幕等无标点字幕也拥有清晰的句间空格（`提到中值定理 如果你的第一反应就是微分中值定理 …`），直接投喂 AI 也能看到断句。

- **问题**：用户反馈在生产环境（真实 Tampermonkey）里，悬停视频弹出进度栏、按播放/暂停都有约 1s 延迟。
- **定位**：用 rAF 帧间隔监测主线程阻塞，把 `GM_setValue` 模拟成 `chrome.storage.local` 大值写入的耗时后**复现了 703ms 的单帧阻塞**。根因是 v2.7.2 引入的「持久层写入延后到空闲帧」——延后本身没错，但 `chrome.storage.local` 的写入是同步桥接，上百 KB 的值会阻塞主线程数百毫秒，而空闲帧正好落在用户悬停进度条、按播放/暂停的时刻。v2.7.2 之前它是阻塞点击（用户能归因），改成延后后阻塞一个随机的后续交互，反而更难察觉。
- **修复**：字幕行缓存**按前缀直接禁止写 GM 持久层**，只留内存 + `sessionStorage`。判断依据是三类属性——体积大（长视频上百 KB）、写入频繁（每切一个视频/分P 一次）、重取便宜（一次接口调用），为它承受阻塞不值得。ASR 识别结果相反（一次性写入、用户本来就在等、重跑要计费），保留持久化。另加 128KB 体积兜底。
- **顺带修**：`sessionStorage` 配额满时原先直接 return，导致字幕行缓存永远写不进去、淘汰逻辑也失效；改为配额满先淘汰最早条目再重试一次。
- **验证**：同一实验条件下 `blockedFrames` 从 `[703]` 变为 `[]`，`maxGap` 22ms（正常帧时间），GM 写入 0 次而 `sessionStorage` 仍正常写入。功能回归：Ctrl+F 读出 365 条字幕、检索 9 命中、Enter 跳转 553.9s→6.3s、整篇与章节复制均 0 网络请求、GM 存储中不再出现字幕行条目。
- **单测**：20 + 28 + 46 组断言全过。
